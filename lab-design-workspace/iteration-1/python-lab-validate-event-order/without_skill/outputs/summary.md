## Lab content

Business scenario: an IoT temperature-sensor fleet writes readings to
`sensor_events.csv` in network-arrival order, which is not guaranteed to
match the true chronological order (`event_ts`). A production fault
scanner (`spike_report.py`) wrongly assumes file order == chronological
order. The student implements `detect_out_of_order()` (running-max
per-device comparison) and `reorder_events()` (chronological
reconstruction with a `sequence_no` tie-break and an explicit
missing-timestamp rule) in `order_check.py`.

Dataset: 16 deterministic rows across 5 devices (`D-01`..`D-05`),
covering: in-order baseline, a headline out-of-order case that both
creates a false alarm and hides a real spike, a same-timestamp tie
requiring `sequence_no` as tie-break, a missing-timestamp row, and a
cascading two-out-of-order-rows-in-a-row case that specifically defeats
a naive "compare to previous row only" implementation.
